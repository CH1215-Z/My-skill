# 릴리스

릴리스는 받아 쓰는 사람이 있는 버전이라 되돌리기 어렵다. **사용자가 분명히 말했을 때만** 하고("릴리스 해줘", "배포", "ISO도"), 하면 빠르게 끝까지 확인한다. 고치는 일이 끝나도 스스로 릴리스하지 않고 "릴리스 해줘 하시면 X로 올리겠습니다"라고 묻는다.

## 0. 프로젝트 설정 (CLAUDE.md·README·CI에서 찾고, 없으면 한 번 묻고 CLAUDE.md "Release"에 적어 둔다)
버전 파일과 규칙 / 변경 기록 파일과 형식 / 푸시할 브랜치·커밋 끝줄 / 릴리스 시작 방법(태그, CI workflow, 빌드 스크립트)과 결과물 위치 / 시험 명령과 시간 / 덤 결과물(설치 이미지 등) 요청 방법.

## 1. 준비
작업 트리 깨끗한지(`git status --short`) → 버전 +1 → 변경 기록에 "릴리스 X (사용자 요청 '…')" + 들어간 항목 → 덤 결과물 요청도 같은 커밋.

## 2. 실행 — 기다리는 시간을 겹친다
푸시 직후 **같은 응답에서** CI/빌드 실행과 전체 시험을 동시에. 시험이 실패하면 공개 전에 실행 취소. 결과물은 예상 시간부터 짧은 간격으로 확인(`scripts/wait_release.sh owner/repo tag`).

## 3. 보고
버전, 결과물 수, 시험 결과(숫자), 들어간 것 3~6줄(사용자 말로), 덤 결과물 받는 법, 실장비에서 확인할 것.

## 주의
빌드 머신이 꺼져 있으면 대기에서 멈춘다 — 알린다. 릴리스 뒤 같은 브랜치에 커밋하면 "같은 버전 번호에 다른 코드"가 생길 수 있다 — 알린다.
