# 프로젝트 기억

세션이 끝나거나 대화가 요약돼도 같은 질문·같은 실수를 반복하지 않게 하는 것이 목적이다.

## 1. 작은 단위로 끝낸다
- 한 가지 일(버그 하나, 기능 하나) = 커밋 하나 + 변경 기록 한 항목 + 푸시.
- 커밋 메시지는 영어 한 줄 요약 + 항목 번호, 끝에 세션이 요구하는 줄.

## 2. 변경 기록 항목 형식
```
## YYYY-MM-DD (번호) — 제목 (누가 왜: 사용자 요청 "…" / 현장 사진 / 버그)
- 현상/요청: …
- 원인: … (확정/추정)
- 고침: … (`파일·함수 이름`)
- 확인: 시험 이름·개수, 화면 확인. [현장 미확인: …]
- 다음: … (있으면)
```
- 사용자가 고른 안과 버린 안을 같이 적는다("A-1/A-2/B 중 B").
- 되돌린 경우도 항목을 남긴다("968의 ~를 되돌림, 사용자 '…'").

## 3. CLAUDE.md에 올릴 것
- 사용자 결정 중 앞으로도 지킬 규칙(예: "릴리스는 말할 때만", "UI는 예시 먼저").
- 다시 조사하지 않아도 되는 확정 사실(구조, 장비 값, 형식). 이미 있으면 고친다, 중복하지 않는다.
- 첫 줄 근처에 "여기를 먼저 보고, 다시 분석하지 말 것" 같은 안내.

## 4. 사용자와 말할 때
- 사용자 언어로, 요약·재시작 뒤에도 같은 언어 유지(CLAUDE.md에 적어 둔다).
- 끝날 때 "남은 것"(릴리스 대기 중인 항목 번호, 답을 기다리는 질문)을 한두 줄.

## 5. 길거나 혼자 도는 작업의 결정 기록
- 결정 지점마다 한 줄씩 덧붙이는 기록 파일(예: `.audit/<작업>.tsv`, 기본은 git 밖): 시각 / 단계 / 결정 / 이유 / 증거(파일·명령·출력 위치, 글 말고 가리키는 것) / 결과(시험 초록, 되돌림, 미결).
- 덧붙이기만 한다. 잘못된 결정은 고치지 말고 새 줄로 대체한다. 모든 행동이 아니라 갈림길만.
- 끝날 때 기록과 실제로 한 일을 맞춰 보고, 증거가 약하거나 확인을 건너뛴 줄을 답 끝에 "주의"로 알린다.
