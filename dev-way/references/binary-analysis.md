# 빌드된 프로그램 분석 (소스가 아닌 것)

실행 파일, 라이브러리, 앱 묶음(APK, Electron/asar, .NET), 펌웨어, 웹 번들, 크래시 덤프, 네트워크 캡처처럼 **만들어져 배포된 것**에 대한 질문일 때. 소스가 있고 질문이 소스에 관한 것이면 소스를 읽는 게 빠르다.

도구: **craft-anything** 또는 **REA(rea-agents)** MCP. 설치돼 있으면(없으면 `scripts/setup_tools.sh`) 그 도구 목록·스키마를 믿고 바로 시작한다(매번 진단 금지). 없으면 `scripts/setup_tools.sh`가 rea를 등록한다(묻지 않음, 사용자 허락됨; 추가·멱등·백업). 도구는 다음 세션부터 보이므로 그동안은 아래 명령으로. 관계없는 프로그램은 설치하지 않는다. 도구 없이 할 수 있는 것: `file`, `strings`, `objdump`/`readelf`, `npx asar extract`, unzip, ILSpy 계열.

## 방법
1. **질문을 목록으로**: 답해야 할 질문과 필요한 증거. 대상을 사용자가 안 정했으면("내 앱") 먼저 묻는다 — 예시 대상을 고르지 않는다.
2. **대상 종류로 길 정하기**: asar/JS → JS 앱 분석, zip/apk/ipa/msix/dmg/pyinstaller → 열어서 요약, Android → 패키지 분석, .NET → 관리 코드 분석, 펌웨어 → 펌웨어 추출, 네이티브 → 바이너리 열기, 캡처(HAR, PCAP) → 캡처 분석. 파일 이름이 아니라 형식 파서로 판단.
3. **요약 먼저, 필요한 부분만 페이지로.** 같은 호출을 바뀐 입력 없이 반복하지 않는다. 잘린 미리보기는 불완전하다.
4. **관측 / 도출 / 추론 / 모름**을 구분해 적는다. 결론마다 증거 ID나 파일:오프셋. 정적 분석을 실행을 본 것처럼 말하지 않는다. "못 찾음"은 찾은 범위까지만 증명한다 — 범위를 적는다.
5. **예측 후 확인**: 도구를 돌리기 전에 기대 결과를 적고, 다르면 가설을 고친다.
6. 독립된 질문만 나눠서 병렬로.
7. **발견 장부**: 결론 ↔ 증거 ↔ 확신도 ↔ 찾은 범위 ↔ 남은 미지수. 끝내기 전에 질문마다 답함/부분/미해결 표시 — 필요한 질문이 열려 있으면 완료라고 하지 않는다.
8. 긴 조사는 끝날 때 인계 메모: 지금 상태, 다음 할 일, 함정(막다른 길, 느린 도구, 헷갈리는 문자열).

## 안전
합법적 연구·허가된 분석만. 대상 실행·주입·변조는 사용자의 명시적 결정 없이는 하지 않는다. GUI 분석 DB(IDA 등)를 저장·덮어쓰지 않는다. 비밀값은 가린다.
