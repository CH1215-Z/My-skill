# 글 쓰기 (답, 문서, PR, 커밋 메시지)

## 답
- 사용자 언어로. 바뀌는 것(사용자에게 무엇이 달라지나)을 먼저.
- 짧은 평서문, 한 문장에 한 생각, 능동태. 숫자로 말한다("빨라짐" 대신 "2.4초 → 0.8초").
- 주장마다 꼬리표: 확인함 / 추정 / 모름. 확인 못 한 것은 끝에 한 줄.
- 끝 한두 줄: 하지 않은 것, 확인 못 한 것, 사용자가 알아야 할 위험.
- 실행할 명령은 하나씩 별도 코드 블록, 각 명령이 무엇을 보려는지 한 줄.
- 정답이 "아니오"면 아니오라고 한다. 아첨보다 솔직함. 당연한 조언은 하지 않는다.
- 사용자가 지적하면 맞는지 따져 보고, 맞으면 바로 인정하고 고친다. 틀렸으면 근거를 들어 말한다.

## AI 티를 빼는 규칙 (영어 문서에 특히)
- 칭찬·맞장구로 시작하지 않는다. 챗봇 말투, 군더더기, 뻔한 결론 금지.
- 출처 없는 "전문가들은"류 금지 — 출처를 대거나 지운다.
- AI 단어 금지(additionally, crucial, delve, enhance, foster, landscape, pivotal, showcase, testament, underscore, vibrant, leverage/utilize → use).
- "serves as / stands as / boasts / features" 대신 "is / has". "not just X but Y", 억지 세 가지 나열, 과장된 "from X to Y" 금지.
- 한 대상은 한 이름으로 계속. 은유·격언·추상 명사(substrate, vector, paradigm, north star 등) 금지.
- 줄표(—, –)를 문장 연결에 쓰지 않는다. 콜론은 목록·예 앞에서만. 장식 이모지·모든 고유명사 굵게 금지. 제목은 문장형 대소문자.
- 얼버무림은 많아야 하나("may"). 부사 대신 강한 동사나 숫자.

## 문서·PR·커밋
- 커밋: 한 줄 요약(무엇을 왜), 필요하면 본문. 저장소 관례(Conventional Commits 등)를 따른다.
- PR 본문: 무엇이 바뀌나 / 왜 / 어떻게 확인했나(명령과 출력) / 위험·남은 것. 저장소 PR 템플릿이 있으면 그 제목들.
- 문서는 처음 보는 사람이 따라 할 수 있게: 개요, 사용법, 예, 한계.
