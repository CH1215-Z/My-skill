# UI 예시 → 선택 → 구현 → 확인

말로 설명한 UI는 서로 다르게 상상하기 쉽다. 그래서 **실제 화면 그림**을 먼저 보여 주고 고르게 한다. 버그 수정은 이 단계 없이 바로 고친다.

## 1. 실제 화면 띄우기
- 데스크톱(리눅스): `scripts/xvfb_app.sh <디스플레이번호> <폭x높이> -- <앱 실행 명령>` → 가상 화면에 앱, `s0.png` 저장.
  조작은 `scripts/x.sh <디스플레이번호> click X Y | type 글자 | key Return | shot 이름`.
- 웹: Playwright로 페이지를 열어 `page.screenshot`(사람이 볼 그림은 deviceScaleFactor 2).
- 데이터는 복사본을 쓰고, 언어 설정은 사용자 언어로.
- 좌표는 먼저 전체 화면을 한 번 찍어 보고 정한다. 입력이 다른 칸으로 가면(포커스) 칸을 먼저 클릭.

## 2. 예시 만들기
- 각 안을 **임시 코드**로 만든다(필요하면 화면용 가짜 값). 빌드 → 같은 데이터·같은 조작으로 찍기.
- ImageMagick으로 같은 영역을 자르고 A/B/C 라벨을 붙여 한 장으로(`convert a.png b.png -append`).
- 찍은 뒤 **임시 코드를 되돌리고 다시 빌드**한다(`git checkout <파일>`). 예시 코드가 커밋되면 안 된다.
- 보낼 때: 각 안 한두 줄, 추천 하나와 이유, 정해야 할 세부 질문 하나.

## 3. 구현 뒤 확인
- 같은 방법으로 실제 동작(입력 → 적용 → 결과, 다시 켰을 때 유지)을 찍어 보낸다.
- 느림 문제는 스톱워치 로그를 임시로 넣어 숫자로 전후 비교하고, 측정 코드는 되돌린다.
  목록이 느리면 "보이는 줄만 만드는지(가상화)"부터 본다 — 템플릿을 바꾸면서 가상화가 꺼진 경우가 흔하다.
- 키보드 이동(Enter·화살표)처럼 화면 밖 행에 닿는 동작도 직접 눌러 확인한다.
