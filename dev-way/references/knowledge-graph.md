# 코드 지식 그래프

도구: **graphify** (CLI + 스킬). 설치돼 있을 때 쓴다.

## 한 번 만들고, 그 뒤엔 갱신과 검색만
- **처음 한 번(전체 생성)**: 프로젝트 구성이 어느 정도 잡혔을 때 — 주요 폴더·모듈과 설명 문서(README, 명세, 설명서)가 생기고, 여러 파일에 걸친 질문이 늘기 시작할 때. 이때 문서까지 포함해 한 번 만든다(`/graphify .`, 문서·이미지 의미 추출에 시간·토큰이 드니 규모를 알리고 승인받는다). 아주 초기(파일 몇 개)에는 만들지 않는다 — grep이 낫다.
- **그 뒤(매번)**: 만들지 않는다. `graphify update .`(코드만, 모델 없음, 약 1분)로 갱신하고 `query` / `affected` / `path` / `explain`으로 검색만.
  - 갱신 시점: 커밋이 몇 개(대략 5개) 쌓였을 때, 또는 구조 질문·여러 파일 수정 전.
  - 문서가 크게 바뀌었을 때(새 명세·설명서 여러 개)만 문서 부분을 다시 추출(`/graphify . --update`) — 이것도 먼저 묻는다.
- 그래프가 있는지는 `graphify-out/graph.json`으로 안다. 있으면 "그 뒤" 단계다.

## 언제 만들까 (그래프가 아직 없을 때)
- 이미 `graphify-out/graph.json`이 있으면 질문은 바로 `graphify query "<질문>"` — 다시 만들지 않는다.
- 없으면: 한 번 찾는 질문("X는 어디 정의", "Y를 누가 부르나")은 grep/파일 읽기가 빠르고 공짜다. 그래프가 가치 있는 때: 같은 코드에 질문이 많을 때, 크거나 낯선 코드, 텍스트 검색으로 안 보이는 연결(문서↔코드, 여러 문서), 구조 질문(묶음, 다리, 순환 import).
- 코드 구문 추출은 빠르고 공짜, 문서·논문·이미지의 의미 추출은 모델을 돌려 시간·토큰이 든다 — 큰 문서 묶음이면 비용을 먼저 말한다.

## 명령어로 직접 쓴다 (토큰)
- graphify **스킬**을 부르면 설명서(약 1만 토큰)가 실린다. 그래프가 있으면 CLI만: 이 명령들은 모델을 부르지 않고 로컬에서 계산하며, 결과만 대화에 들어온다(`affected` 수백 토큰, `query`는 `--budget`으로 상한).
- **여러 파일에 걸친 코드 수정 전**: 바꿀 함수마다 `graphify affected "<정확한 이름>" --depth 2`, 필요하면 `graphify query "<질문>" --budget 800`. 이름이 겹치면 `graphify explain`이 후보를 보여 준다.
- 그래프에 안 잡히는 연결(XAML·템플릿 바인딩, 문자열·리플렉션 호출, 설정 파일)은 `grep`으로 한 번 더. 그래프는 검색을 더하는 것이지 대신하지 않는다.
- **갱신**: 커밋이 몇 개 쌓였거나 구조 질문 전에 `graphify update .`(코드만, 수만 노드 저장소도 약 1분, 모델 호출 없음). 문서·이미지 의미 추출은 비용이 크니 먼저 묻는다.

## 명령
```
graphify <경로>                  # 전체(HTML 시각화 + JSON + GRAPH_REPORT.md)
graphify update <경로>           # 코드만 다시 읽어 갱신(모델 없음)
graphify affected "X" --depth 2  # X를 바꾸면 영향받는 곳(거꾸로 따라가기)
graphify query "<질문>"          # 넓게(BFS), --dfs 는 경로 따라가기, --budget N
graphify path "A" "B"            # 두 개념 사이 최단 경로
graphify explain "노드"           # 노드 설명
```
결과는 `graphify-out/`. 추출된 연결은 EXTRACTED / INFERRED / AMBIGUOUS로 구분되니, 답할 때 그 구분을 그대로 밝힌다.
