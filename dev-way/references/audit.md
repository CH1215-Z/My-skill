# 저장소 전체 점검 · 미뤄 둔 일 목록

## 전체 점검 (코드를 바꾸지 않는 한 번의 보고서)
물려받아서 문제가 생기면 호출될 사람처럼 본다. 기준·찾을 것·보고 전 확인·출력 형식은 `review.md`와 같고, 다른 점만:
- 범위: 사용자가 말한 폴더·패키지, 없으면 전체.
- 지도부터: README, 배포·빌드 설정, 의존성 목록, 진입점(main, 라우트, 핸들러, 작업, CLI), 시험. 주요 흐름을 끝까지(사용자 입력, 돈, 인증, 데이터 쓰기, 백그라운드 작업, 프로세스 간 공유).
- 큰 저장소는 실수 비용이 큰 곳부터 깊게, 읽지 않은 부분은 밝힌다.
- 안 쓴다고 하기 전에 시험·고정 데이터·설정·문자열·동적 참조까지 전체를 grep.
- 군더더기 추가 항목: 안 쓰는 옵션·플래그·설정, 구현 하나뿐인 인터페이스, 제품 하나뿐인 팩토리, 전달만 하는 래퍼, 몇 줄로 될 일을 하는 의존성.
- 출력: `이 저장소가 하는 일:` + 가정한 부하. 지적 최대 20개(빠진 작은 것 개수). 끝: `판정:` 한 줄 / `줄일 수 있는 것: -N줄, -M 의존성` / `확인 못 함:`.

## 미뤄 둔 일 목록 (shortcut ledger)
`shortcut:`(옛 `ponytail:`) 주석을 모아 미룬 일이 조용히 영구가 되지 않게 한다.
```bash
git grep --no-index --exclude-standard -nE '(#|//|/[*]) ?(shortcut|ponytail):'
```
(사용자가 다른 표시어를 말하면 그것으로. 키보드 단축키 설명처럼 미룬 일이 아닌 것은 뺀다.)
출력: 파일별로 `<파일>:<줄>, <단순화한 것>. 한계: <…>. 바꿀 때: <…>.` 바꿀 때(조건)가 없는 줄은 `조건 없음` 표시 — 이것들이 썩는다. 끝: `<N>개, 조건 없음 <M>개.` 없으면 `미룬 일 없음.` 읽기만 하고, 파일로 남기려면 묻는다.
